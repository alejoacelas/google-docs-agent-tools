# Claude's Google Docs connector: main gaps (draft, 2026-10-06)

Alejo Acelas | Last updated: Oct 6, 2026

The connector passes raw Google API calls through: `read_doc` is [`documents.get`](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/get) and `update_doc` is [`documents.batchUpdate`](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/batchUpdate). Each row comes from fresh Claude Code sessions (Opus 5.5, two runs per request) given one ordinary request on a synthetic project plan, with the document inspected afterwards. Some rows also have Claude chat runs on claude.ai. The task prompts, fixture, run records and harness are in the [public repository](https://github.com/alejoacelas/google-docs-agent-tools). Earlier end-to-end results and API probes are in its [results viewer](https://alejoacelas.github.io/google-docs-agent-tools/).

## Failures I disliked most

| # | Gap | What Claude does | Why | What the tests showed |
|---|---|---|---|---|
| 1 | Pending suggestions | Chat states a pending suggested clause as fact (2 of 2 runs). Claude Code flags pending suggestions correctly (4 of 4). | Drive's `read_file_content`, which chat prefers, prints inserted and deleted text side by side with no markers. A budget cell reads `$5,500$4,000`. | `read_doc` does mark suggestions, but it has no option to show the accepted or original view. |
| 2 | Ticked checkboxes | In a status summary, says no checklist items are ticked (1 of 2 runs). Asked directly, gets it right (2 of 2). | `documents.get` doesn't return checked state. | Claude Code works around it with Drive's Markdown export, which prints `- [x]`. Chat inferred "all four look open" from the missing strikethrough. In a Markdown update, one run told the user to tick two items that were already ticked. No request can tick an item. |
| 3 | Inserting a local image | Uploads it privately to Drive. The insert fails. Asks the user to set link sharing or insert it by hand. | `insertInlineImage` needs a public URL. `share_file` only shares with an email address. | Google's error: "The provided image should be publicly accessible". Claude offered public hosting only with permission. The private upload stays in Drive. |
| 4 | Nesting a list item | Adding a sub-point: fakes it with indentation (2 of 2). Indenting an existing item: asks the user to press Tab (2 of 2). | `batchUpdate` has no request to change an item's nesting level. Re-creating the bullets resets them to Google's presets, and none is a dash. | Each run took 2–3 minutes testing on scratch copies. One copy was left in the user's folder. The faked sub-point is top-level in exports. Chat changed the whole list to ●/○. |

## Other gaps found in testing

| # | Gap | What Claude does | Why | What the tests showed |
|---|---|---|---|---|
| 5 | Accepting or rejecting suggestions; replying to or resolving comments | Retypes the suggested text as a direct edit. Says it can't reply or resolve. Gives the user UI steps. | Anthropic's `google-workspace` skill says this is impossible. `update_doc` already accepts Google's preview requests `acceptSuggestion`, `rejectSuggestion` and `addCommentReply`. | The retyped "accept" looks right, but version history records Claude's edit, not an accepted suggestion. Claude says so. One chat run drove the user's Chrome and clicked through the Docs UI instead, without asking. Another posted the reply through a separate Google connector the user had installed. The belief carries into other tasks: both Markdown-update runs left suggestions for the user to reject, and one adjacent-suggestion run said it can't add comments. |
| 6 | Editing text that has a comment | Claude Code keeps the comment on the whole new amount (2 of 2). Chat shrank it to "$" and said so. | A comment keeps only its original characters that survive an edit. The skill teaches replacing only the changed characters. | Chat had read the skill but deleted the old amount before inserting the new one. The trick needs shared characters: an earlier "pilot teams" → "early adopters" edit shrank the comment to "early ". One run briefly left "$124,00" from an index error before fixing it. |
| 7 | Version history | Says it can't see earlier versions. Points the user to File → Version history. | No tool lists revisions. Drive's `download_file_content` with a revision ID returns "not yet supported". | Claude tried `gcloud` and a local CLI, then narrowed the edit to a time window from the file's timestamps. |
| 8 | Moving a section | Stops and asks the user to cut and paste (2 of 2). | No move request exists. A move means deleting and retyping. | Claude named the losses correctly: the comment detaches, the pending suggestion is lost or re-added under Claude's name, dash bullets become round, and the heading's new ID breaks outside links. |
| 9 | Table of contents | Inserts a list of heading links. Says it won't update itself (2 of 2). | `batchUpdate` has no request to insert Google's table of contents. | All links pointed to the right headings and matched the doc's link style. One run added a "Contents" heading that now appears in the outline. |
| 10 | Adding a suggestion next to an existing one | Adds the sentence in suggest mode. It joins the existing pending suggestion (2 of 2). Claude reports this and offers to redo it later. | Docs merges touching suggestions from the same account. Accepting or rejecting one now decides both. | Claude detected the merge by reading the doc back and finding the old suggestion's ID on its text. Any position at the end of that bullet touches the old suggestion, so Claude couldn't avoid it. |
| 11 | Copying a doc | Makes a copy without comments or suggestions (2 of 2). Says so. Leaves the copy in Drive. | Drive's `copy_file` copies only the text. The editor's "Copy comments and suggestions" option has no API equivalent. | The copy keeps the original text: the suggested $5,500 reads $4,000. Claude pointed the user to File → Make a copy. It offered to re-create comments, which would show the user as author and today's date. |
| 12 | Reading a doc | `read_doc` returns more than the tool-result limit for a short doc with comments. Claude Code saves it to a file and parses it with `jq`. Chat says it's "too large to read in full". | `documents.get` returns raw JSON: styling for every text run, and nine nesting levels for every list. | About 50,000 characters came back for under 2,000 characters of text; 12,500 of them were list definitions. After the truncated read, chat got the checklist wrong. |

**Held up in these tests:** updating a doc from edited Markdown. Both runs changed only the edited words and kept the comments, suggestions, heading link and header. An earlier end-to-end task failed by unmerging a merged table cell; this test's doc had no merged cells.

**Found only by API probes so far:** `createHeader` with type `FIRST_PAGE` returns "Internal error encountered". `insertRichLink` returns "Permission denied" on a doc the user owns. `insertTableColumn` resets neighbouring fixed column widths to 16 pt.
